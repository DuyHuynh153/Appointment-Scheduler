# ADR-004: Environment-driven Feature Toggles

**Status:** Accepted
**Date:** 2026-08-01

## Context

Some behaviors (auto-assignment of technician/bay, strict overlap validation, structured logging format) are the kind of thing that, in a real product, would need to be enabled/disabled incrementally per environment or per dealer without a full redeploy.

## Decision

Implement three environment-variable-driven feature toggles, loaded once at startup into a settings object (`core/config.py`) and read by the service layer:

- `ENABLE_AUTO_ASSIGN`
- `ENABLE_OVERLAP_VALIDATION`
- `ENABLE_STRUCTURED_LOGGING`

No external feature-flag service (e.g. LaunchDarkly) is introduced — this is a static, environment-scoped toggle, not a dynamic per-request/per-user flag system.

## Rationale

- Demonstrates the _pattern_ of safe incremental rollout (e.g. auto-assignment could be enabled for one dealership while keeping manual assignment for others) without needing a deployment pipeline or third-party service to prove it.
- Keeps the mechanism intentionally simple: three booleans read from environment variables at startup is enough to show the pattern is understood, without over-building a flag system nobody asked for.
- `ENABLE_OVERLAP_VALIDATION=false` also has a practical use during local development/manual testing (seeding overlapping test data without the check getting in the way), which is a legitimate secondary reason to have it.

## Alternatives Considered

- **No toggles, everything always on** — simplest, but gives up the chance to demonstrate rollout-safety thinking, which is a pattern product companies value.
- **Full feature-flag service (LaunchDarkly/Unleash) or per-request dynamic flags** — disproportionate to a one-week assessment; would be justified only with real multi-tenant rollout requirements that don't exist here.

## Consequences

- Toggles are process-wide (require a restart to change), not per-request or per-dealer dynamic — acceptable given the stated scope; called out explicitly if asked "does this support per-dealer toggles?" (answer: not yet, but the settings object is the natural extension point).
